# Правила спецификаций (HDD Hackathon Edition)

Статус: reference / current · сверено: 2026-09-11

Минималистичный протокол Handoff-Driven Development, адаптированный под условия хакатона: нулевая бюрократия, максимальная экономия контекста LLM, защита от регрессий и потери фокуса при смене сессий/агентов.

---

## 1. Структура и карта (Reachability)

- Входная точка всей документации — корневая карта [specs-map.md](specs-map.md).
- **Инвариант достижимости:** любой `.md` файл в директории `specs/` обязан быть достижим по markdown-ссылке от `specs-map.md`. Недостижимый файл — сирота, агент его не найдет.
- Аудит ссылок и сирот запускается одной командой: `python3 specs/audit.py`.

---

## 2. Жанры и статусы документов

Каждый файл спецификации `spec-*.md` под заголовком содержит ровно одну мета-строку:

```markdown
Статус: <жанр> / <статус> · сверено: YYYY-MM-DD
```

### Жанры:
| Жанр | Назначение на хакатоне |
|---|---|
| `as-built` | Описание реально работающего кода. Обязано соответствовать кодовой базе. |
| `plan` | План реализации фичи/спринта. Временный документ. После выполнения удаляется или архивируется. |
| `reference` | Справочники, правила, API-контракты, таблицы констант. |
| `log` | Журнал принятых архитектурных решений (ADR). |

### Статусы:
| Статус | Значение |
|---|---|
| `current` | Актуально, проверено с кодом на указанную дату. |
| `stale` | **Главный статус хакатона!** Код изменился в спешке, спека не обновлена. Сигнал агенту: *«Спеке слепо не верить, перепроверить код»*. |
| `draft` | Черновик, идея, еще не утверждено. |
| `accepted` | Принято к немедленной реализации. |
| `archive` | Устарело, сохранено для истории. |

## 3. Бэклоги задач

- [backlog.md](backlog.md) — только открытые задачи (короткий список).
- [backlog-resolved.md](backlog-resolved.md) — решенные задачи с кратким описанием решения (база прецедентов).
- **Инвариант:** задача существует **ровно в одном** из этих двух файлов. Закрыли задачу в коде → переместили строку из `backlog.md` в `backlog-resolved.md`.

---

## 4. Рабочие треки и Handoff

- Список активных задач — [TRACKS.md](TRACKS.md). Ровно одна строка на трек (ссылка на handoff, статус, дата, следующий шаг).
- Файл `handoff-<track>.md`:
  1. **Что загрузить в контекст:** конкретный список 2–3 файлов, нужных для задачи.
  2. **Что НЕ загружать:** анти-список тяжелых файлов, чтобы не забивать окно модели.
  3. **Не перерешивать (Locked Decisions):** принятые архитектурные решения с обоснованием. Запрещено пересматривать без веской причины.
  4. **Состояние:** Done / In Progress / Next step.
- Закрытый трек удаляется из `TRACKS.md`, краткий итог переносится в [TRACKS-LOG.md](TRACKS-LOG.md).
