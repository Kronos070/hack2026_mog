# Воздушный Шар — веб-прототип бонусной игры

Бонусная crash-игра: игрок ставит бонусные баллы и старается забрать растущий выигрыш
до того, как воздушный шар лопнет.

## Как играть

1. На стартовом экране выберите **Тестовый игрок** (баланс 1000 бонусов) или **Администратор**.
2. Выберите тему — зелёный шар (9 уровней) или красный (12 уровней).
3. Задайте ставку — введите свою сумму или выберите пресет — и множитель бустера (x1–x4).
4. Нажмите **Начать** — шар взлетает, коэффициент растёт. Весь раунд проходит на том же
   экране: форма ставки остаётся на месте, но становится недоступной до конца полёта.
5. После первого уровня становится активна кнопка **Забрать**: выигрыш = ставка × коэффициент.
6. Если не успеть до краха — ставка сгорает.

За пройденные уровни, cashout и активацию бустера начисляются игровые очки.
Каждый раунд выдаёт фрагмент коллекции — соберите все 6.

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # продакшен-сборка в dist/
```

По умолчанию приложение работает на встроенном мок-бэкенде (данные в `localStorage`).
Чтобы подключить реальный бэкенд, скопируйте `.env.example` в `.env`:

```bash
cp .env.example .env
npm run dev
```

### Что берётся с реального бэкенда

| Работает через API | Осталось на моке |
|---|---|
| Регистрация и вход (JWT) | Конфигурация игры и админка |
| Профиль, баланс, очки | Турнирная таблица и рейтинг |
| Старт раунда, cashout | Достижения, ранги, коллекция |
| История раундов | Расширенная статистика профиля |
| Полёт по WebSocket `/ws/game` | |

Тестовый администратор на бэкенде: логин `admin`, пароль `admin123`.

**Важно про полёт.** На реальном бэкенде множитель приходит тиками по WebSocket —
клиент ничего не считает сам. В мок-режиме работает локальный движок на
`requestAnimationFrame`. Обе ветки отдают одинаковый снимок состояния, поэтому
сцена и интерфейс не знают, какой источник активен.

## Стек

- **Vite 8** + **React 19** + **TypeScript 6** (strict)
- **Tailwind CSS 4** — CSS-first конфигурация через `@theme`
- **TanStack Query 5** — серверное состояние
- **Zustand 5** — клиентское состояние (сессия, активный раунд)
- **Zod 4** — валидация ответов API
- **React Router 7** — клиентский роутинг
- **Canvas 2D** — сцена полёта, **DOM** — интерфейс поверх неё

### Производительность

Множитель и сцена обновляются покадрово через `requestAnimationFrame` **без ререндеров React**:
игровое состояние живёт в `useRef`, canvas читает его напрямую, текст множителя обновляется
через `textContent`. React перерисовывается только на смену экрана и дискретные события
(активация бустера, cashout).

Позиция шара и линии уровней используют одну шкалу — логарифмическую интерполяцию
между соседними уровнями, поэтому шар всегда совпадает с отметкой своего коэффициента.

## Математическая модель

Точка краха — обратное преобразование Парето:

```
crash = min_crash_multiplier / U^(1/alpha),  U ~ Uniform(0,1)
```

усечённое сверху `max_multiplier`. Рост коэффициента — экспонента с разгоном:

```
multiplier(t) = e^(growth_rate · t^acceleration)
```

При `acceleration > 1` показатель сам растёт со временем: начало полёта пологое
(за первую секунду всего ~x1.11), а дальше кривая круче обычной экспоненты
(x2.23 на 4-й секунде, x9.61 на 8-й). При `acceleration = 1` формула вырождается
в обычную экспоненту.

Границы уровней — геометрическая прогрессия от x1 до x10 с шагом `10^(1/N)`,
где N — число уровней темы.

Значения по умолчанию (`alpha=1.3`, `min_crash=1.3`, `growth_rate=0.1`, `acceleration=1.5`)
подобраны так, чтобы средний раунд длился около 4.5 секунд, а короче 2 секунд были лишь
~3% раундов — иначе игрок не успевает нажать «Забрать».

## Параметры конфигурации

Настраиваются в админ-панели (`/admin`) без перекомпиляции; применяются со следующего раунда.

| Параметр | Описание | По умолчанию |
|---|---|---|
| `alpha` | Крутизна распределения краха; больше — крах раньше | 1.3 |
| `maxMultiplier` | Верхняя граница коэффициента | 100 |
| `minCrashMultiplier` | Минимальный коэффициент краха | 1.3 |
| `multiplierGrowthRate` | Темп роста коэффициента | 0.1 |
| `growthAcceleration` | Разгон кривой: 1 — ровная экспонента, 2 — резкая | 1.5 |
| `pointsPerLine` | Очки за пройденный уровень | 10 |
| `pointsCashoutBonus` | Очки за успешный cashout | 25 |
| `pointsBoosterBonus` | Очки за активацию бустера | 50 |
| `boosterTierValues` | Множители бустеров x1–x4 | [1,2,3,4] |
| `lootProbabilities` | Вероятности уровня бустера по темам | см. конфиг |
| `minWinAmount` | Порог выигрыша для апсейла | 50 |
| `popupTimeout` | Автозакрытие попапа, с | 10 |

### Тело запроса на старт раунда

```json
{ "theme": "green", "cost": 137, "boosterTier": 3 }
```

Сумма ставки произвольная (целое число больше нуля), поэтому **сервер обязан сам проверить**,
что она не превышает баланс — клиентская блокировка кнопки не является защитой.
`boosterTier` (1–4) индексирует `boosterTierValues` из конфига.

### Важно для реализации на Java

Мок отдаёт `crashMultiplier` клиенту при старте раунда — это допустимо только в прототипе,
чтобы анимировать полёт локально. **На реальном бэкенде это поле отдавать нельзя:**

- клиент анимирует коэффициент сам по `startedAt` и `growthRate`;
- при нажатии «Забрать» клиент шлёт свой коэффициент, **сервер пересчитывает его сам**
  по времени запроса и возвращает авторитетное значение;
- о крахе сервер сообщает push-сообщением (WebSocket) или клиент узнаёт при `finish`.

## Реализовано

- Выбор роли (временная замена регистрации)
- Выбор темы, произвольная сумма ставки с пресетами, выбор тира бустера
- Сцена с шаром видна всегда, в том числе между раундами
- Весь игровой цикл на одном экране `/game`: ставка, полёт и итоги без переходов
- Множитель лежит поверх сцены — интерфейс не смещается при старте
- Сцена и лента крашей закреплены под хедером; контент под ними плавно растворяется
- Живой рейтинг на отдельной странице `/leaderboard` с опросом раз в секунду
- Лента последних крашей с цветовой шкалой: красный до x1.2, оранжевый до x2, зелёный от x2
- Турнирная таблица с призовыми местами и таймером до завершения
- Кнопки «Повторить ставку» и «Экспресс-ставка» для мгновенного старта
- Профиль игрока `/profile`: ранг, статистика, достижения и коллекция
- Просмотр чужих профилей `/profile/:id` (данные ботов — мок)
- Достижения `/achievements`: 10 штук, полученные подсвечены, остальные серые
- Уведомление о новых достижениях сверху по центру
- Система рангов по чистой прибыли: от Новобранца до Легенды, может расти и падать
- Аватары — первая буква имени (до появления картинок)
- Живой пейзаж на сцене: холм с деревьями, стаи птиц, облака разной глубины
- Игровой цикл: полёт, рост коэффициента, уровни, крах
- Бустеры: серверный выбор уровня по вероятностям, активация до cashout
- Cashout с сообщением «могли бы забрать больше»
- Экран результатов: выигрыш, очки, награда, автопереход через 10 с
- Цветовая дифференциация множителя (4 ступени)
- Мини-онбординг при первом запуске
- История раундов, правила игры
- Админ-панель с валидацией параметров
- Переключатель светлой и тёмной темы (включая цвета игровой сцены)
- Адаптивность 320–1920 px
- Сохранение состояния в `localStorage`
