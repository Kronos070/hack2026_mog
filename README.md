## 🧭 Инструкция для проверяющих (User Flow)

Для быстрой и всесторонней оценки решения рекомендуем пройти два основных сценария:

### 🎮 Сценарий 1: Пользовательский путь игрока (Регистрация ➔ Игра ➔ Мета)

1. Откройте [**mog-stoloto.duckdns.org**](https://mog-stoloto.duckdns.org).
2. **Вход / Регистрация:**
   - Вы можете зарегистрировать новый аккаунт через вкладку *«Создание аккаунта»*, либо
   - Воспользоваться блоком **«Быстрый вход для демонстрации»** внизу экрана и нажать кнопку **«Игрок»**.
3. **Выбор темы и настройка раунда:**
   - Выберите тему шара:
     - 🟢 **Зеленый шар** — 9 уровней высоты, умеренный риск, классическая динамика.
     - 🔴 **Красный шар** — 12 уровней высоты, повышенный азарт и крутые множители.
   - Задайте сумму ставки бонусов (вручную или быстрыми пресетами).
   - Выберите тир бустера (x1–x4), увеличивающего итоговые очки.
4. **Игровой цикл:**
   - Нажмите **«Начать»** — шар поднимается, сервер в реальном времени стримит 60 FPS тики по WebSocket.
   - Преодолевайте уровни высоты и следите за динамическим ростом множителя.
   - Успейте нажать **«Забрать» (Cashout)** до краха шара.
5. **Мета-игра и удержание:**
   - Проверьте начисление бонусных очков и выигрыша.
   - Соберите коллекцию из **9 уникальных фрагментов пазла** (с защитой от дубликатов через Pity Timer).
   - Ознакомьтесь с каталогом из **10 достижений** и динамическим рангом (от *Новобранца* до *Легенды*).
   - Перейдите в раздел **«Турнир»** — оцените живое обновление лидерборда по SSE (1 Гц) и призовой фонд топ-3.

---

### 👑 Сценарий 2: Панель администратора (Hot-Reload и управление)

1. Если вы авторизованы как игрок — **выйдите из аккаунта** (иконка/кнопка выхода в шапке или профиле).
2. На экране входа (`/login`) в нижней панели *«Быстрый вход для демонстрации»* нажмите кнопку **«Администратор»**  
   *(Либо введите вручную: логин `admin`, пароль `admin123`)*.
3. Вы будете перенаправлены в панель управления [**/admin**](https://mog-stoloto.duckdns.org/admin):
   - **Горячая переконфигурация (Hot-Reload):** меняйте любой из 10 параметров (крутизну Парето $\alpha$, темп роста множителя, очки за уровни, бустеры, кэшаут) — новые настройки вступают в силу **мгновенно в RAM без перезагрузки бэкенда**.
   - **House Edge & RTP:** проверьте встроенный балансир отдачи платформы (RTP 96%).
   - **Управление турниром («Force Settle»):** нажмите кнопку принудительной финализации турнира, чтобы распределить призы топ-3 игрокам и запустить новый цикл.

## 💻 Инструкция по локальному запуску

Вы можете запустить проект локально двумя способами: через готовые Docker-контейнеры либо в режиме разработки (Dev Mode).

### Вариант 1. Быстрый запуск всех сервисов в Docker (Рекомендуется)

Требуется установленный **Docker** и **Docker Compose**.

1. Клонируйте репозиторий и перейдите в корень проекта:
   ```bash
   git clone <url-репозитория>
   cd hack2026_mog
   ```

2. Соберите и поднимите все контейнеры (PostgreSQL, Backend, Frontend):
   ```bash
   docker compose up --build
   ```

3. Сервисы будут доступны по следующим адресам:
   - **Frontend:** [http://localhost:3000](http://localhost:3000)
   - **Backend API:** [http://localhost:8080/api](http://localhost:8080/api)
   - **Swagger UI:** [http://localhost:8080/q/swagger-ui/](http://localhost:8080/q/swagger-ui/)
   - **База данных PostgreSQL:** `localhost:5432` (`mog_db` / `mog_user` / `mog_pass`)

---

### Вариант 2. Запуск в режиме разработки (Dev Mode с Hot-Reload)

Идеально подходит для внесения правок и отладки исходного кода.

#### 1. Системные требования:
- **Java:** JDK 21 LTS (рекомендуется Eclipse Temurin или GraalVM)
- **Node.js:** v20.x или v22.x + npm
- **Docker:** для запуска базы данных PostgreSQL

#### 2. Запуск базы данных:
Из корня проекта поднимите только PostgreSQL:
```bash
docker compose up -d postgres
```

#### 3. Запуск Quarkus Backend:
Откройте терминал, перейдите в папку `backend` и запустите Dev-сервер:
```bash
cd backend
./mvnw quarkus:dev
```
- Бэкенд скомпилируется и запустится на порту `8080`.
- Применяются автоматические миграции Flyway (`V1.0.0` – `V1.0.5`).
- Включен **Quarkus Live Reload**: любые правки в коде Java применяются мгновенно без перезапуска!
- Консоль разработчика: [http://localhost:8080/q/dev/](http://localhost:8080/q/dev/)

#### 4. Запуск React Frontend:
В соседнем терминале перейдите в папку `frontend`:
```bash
cd frontend
npm install

# Убедитесь, что настроен .env (или скопируйте из примера):
cp .env.example .env

npm run dev
```
- Приложение запустится на Vite Dev Server: [http://localhost:5173](http://localhost:5173) (с поддержкой Fast Refresh).

---

### Вариант 3. Продакшен-сборка (с Caddy и SSL)

Для развертывания на боевом сервере с автоматическим получением SSL-сертификатов Let's Encrypt используется конфигурация:

```bash
# Скопируйте и настройте переменные окружения
cp .env.prod.example .env.prod

# Запустите стек Caddy + Quarkus + Frontend + Postgres
docker compose -f docker-compose-production.yml --env-file .env.prod up -d --build
```

## 🏗️ Архитектура и стек технологий

```
┌─────────────────────────────────────────────────────────────┐
│                 React 19 Frontend (SPA)                     │
│  Vite 8 · TypeScript · Tailwind CSS 4 · Canvas 2D (60 FPS)  │
└──────────────┬───────────────────────────────▲──────────────┘
               │ HTTP REST (JWT)               │ WebSocket /ws/game (60 FPS)
               │                               │ SSE /tournament/.../stream (1 Hz)
┌──────────────▼───────────────────────────────┴──────────────┐
│                 Quarkus 3.x Backend                         │
│  Java 21 Virtual Threads (Loom) · SmallRye JWT · Panache    │
│  Provably Fair (HMAC-SHA256) · RAM Hot-Reload Config        │
└──────────────────────────────┬──────────────────────────────┘
                               │ JDBC / Agroal Pool
┌──────────────────────────────▼──────────────────────────────┐
│                 PostgreSQL 16 Database                      │
│  Flyway Migrations · JSONB Configs · Optimized Indexes      │
└─────────────────────────────────────────────────────────────┘
```

- **Server-Authoritative Physics:** Физика полета, срабатывание бустеров и краш рассчитываются исключительно на сервере. Клиент получает координаты 60 раз в секунду по WebSocket.
- **Java 21 Project Loom:** Обработка каждого отдельного полета шара на легковесном виртуальном потоке (`Thread.ofVirtual()`), что гарантирует масштабируемость до десятков тысяч одновременных раундов.
- **Provably Fair:** Честность каждого раунда криптографически доказуема через HMAC-SHA256 хеш (`serverSeed + clientSeed + nonce`).
- **Отказоустойчивость и производительность:** Hot-Reload конфигураций через `AtomicReference` в RAM обеспечивает нулевой оверхед на чтение параметров во время раунда.
