# Документация API: Связь бустеров и фрагментов (Booster Fragment Economy)

Данный документ описывает новую функциональность бэкенда, связывающую выбор бустеров полета со списанием фрагментов пазла, а также новые ручки конфигурации и гарантии обратной совместимости API.

---

## 1. Концепция и правила механики

1. **Фрагменты как расходуемый ресурс:**
   - Ранее бустеры (x2, x3, x4) выбирались игроком бесплатно перед стартом раунда.
   - Теперь бустеры приобретаются за **фрагменты** (кусочки пазла).
   - Лимит фрагментов у игрока: **максимум 10** (ранее коллекция состояла из 9).
   - Стартовый баланс для всех игроков (новых и существующих): **6 фрагментов**.

2. **Базовая стоимость бустеров (сетка по умолчанию):**
   - **Тир 1 (x1.0):** 0 фрагментов (бесплатный стандартный полет).
   - **Тир 2 (x2.0):** 2 фрагмента.
   - **Тир 3 (x3.0):** 4 фрагмента.
   - **Тир 4 (x4.0):** 6 фрагментов.

3. **Модель покупки:**
   - Покупка происходит **прямо при старте раунда** в `POST /api/game/start`.
   - Игрок указывает желаемый `boosterMultiplier` (или `boosterTier`: 1..4).
   - Если стоимость выбранного бустера > 0, бэкенд проверяет `fragmentBalance` игрока.
   - При достаточном количестве: списывается стоимость бустера, раунд запускается со статусом `IN_PROGRESS`.
   - Фрагменты расходуются как ставка (окончательно при старте, без возврата при краше).
   - При нехватке фрагментов: сервер возвращает ошибку `400 Bad Request` с описанием нехватки (ставка бонусов не списывается).

4. **Дроп фрагментов и Pity Timer:**
   - По завершении раунда (`CASHOUT` или `CRASHED`) проверяется баланс фрагментов игрока.
   - Если `fragmentBalance < 10`: фрагмент может выпасть по Pity Timer (базовый шанс 30% + 20% за каждый пустой раунд). При выпадении баланс увеличивается на +1, а pity сбрасывается в 0.
   - Если `fragmentBalance == 10`: коллекция считается полной, новые фрагменты не выпадают до тех пор, пока игрок не потратит часть фрагментов на бустеры.

5. **Ачивки и радар характеристик:**
   - Достижение `puzzle_collector` («Коллекционер пазлов») засчитывается при удержании на балансе **10 фрагментов**.
   - Ось `collector` в шестиугольнике характеристик (`UserStatRadar`) рассчитывается от текущего баланса:  
     $$\text{Score} = \left(\frac{\min(10, \text{fragmentBalance})}{10.0}\right) \times 7.0 + \text{recentDrops (до 3.0)}$$

## 2. Статус существующих API-контрактов (Zero Breaking Changes)

Все существующие контракты сохранены на 100% без нарушения обратной совместимости с фронтендом:

| Эндпоинт | Статус | Поведение |
| :--- | :--- | :--- |
| `POST /api/game/start` | **Сохранен** | Контракт тела запроса (`StartRoundRequest`) и ответа (`GameRoundStartResult`) не изменился. Если у игрока не хватает фрагментов для бустера > 1, возвращается `400 Bad Request`. |
| `GET /api/users/me` | **Сохранен** | Поле `puzzleTotal` возвращает `10`. Поле `puzzle` возвращает массив `["piece_1", ..., "piece_k"]`, где $k$ равно текущему `fragmentBalance`. Zod-схема фронтенда `profileSchema` валидируется успешно. |
| `POST /api/game/cashout` и WS-события | **Сохранен** | Поле `RewardDto`: `total = 10`, `collected = fragmentBalance`. Поле `pieceId` возвращает `"piece_X"` или `"none"` / `"completed"`. Zod-схема `rewardSchema` валидируется успешно. |
| `GET /api/admin/config` и `PUT /api/admin/config` | **Сохранен** | Поле `boosterCostFragments` опционально при десериализации (при отсутствии ставится `[0, 2, 4, 6]`). Существующий админский фронтенд Zod strip-ит неизвестные поля без ошибок. |

## 3. Новые ручки API

### 3.1. Получить каталог бустеров и стоимость

- **Метод:** `GET`
- **Путь:** `/api/game/boosters`
- **Авторизация:** Не требуется (публичный эндпоинт для клиента)
- **Описание:** Возвращает актуальный список бустеров с множителями и их стоимостью во фрагментах.

#### Пример ответа (`200 OK`):
```json
[
  {
    "tier": 1,
    "multiplier": 1.0,
    "costFragments": 0
  },
  {
    "tier": 2,
    "multiplier": 2.0,
    "costFragments": 2
  },
  {
    "tier": 3,
    "multiplier": 3.0,
    "costFragments": 4
  },
  {
    "tier": 4,
    "multiplier": 4.0,
    "costFragments": 6
  }
]
```

---

### 3.2. [Админ] Просмотр сетки цен бустеров

- **Метод:** `GET`
- **Путь:** `/api/admin/boosters/pricing`
- **Авторизация:** `Bearer <JWT>`
- **Описание:** Возвращает актуальную конфигурацию стоимости бустеров во фрагментах.

#### Пример ответа (`200 OK`):
```json
[
  { "tier": 1, "multiplier": 1.0, "costFragments": 0 },
  { "tier": 2, "multiplier": 2.0, "costFragments": 2 },
  { "tier": 3, "multiplier": 3.0, "costFragments": 4 },
  { "tier": 4, "multiplier": 4.0, "costFragments": 6 }
]
```

---

### 3.3. [Админ] Изменение стоимости бустеров

- **Метод:** `PUT`
- **Путь:** `/api/admin/boosters/pricing`
- **Авторизация:** `Bearer <JWT>` (роль `ADMIN`)
- **Описание:** Обновляет стоимость бустеров во фрагментах. Применяется со следующего раунда.
- **Тело запроса (`Content-Type: application/json`):** Массив ровно из 4 целых неотрицательных чисел (стоимость для тиров 1, 2, 3, 4).

#### Пример запроса:
```json
[0, 2, 4, 6]
```

#### Пример ответа (`200 OK`):
```json
[
  { "tier": 1, "multiplier": 1.0, "costFragments": 0 },
  { "tier": 2, "multiplier": 2.0, "costFragments": 2 },
  { "tier": 3, "multiplier": 3.0, "costFragments": 4 },
  { "tier": 4, "multiplier": 4.0, "costFragments": 6 }
]
```

## 4. Обработка ошибок при старте раунда

Если игрок отправляет запрос на старт раунда с бустером, но у него недостаточно фрагментов:

#### Запрос:
```http
POST /api/game/start
Authorization: Bearer <jwt_token>
Content-Type: application/json

{
  "betAmount": 100,
  "theme": "green",
  "boosterMultiplier": 3
}
```

#### Ответ при нехватке фрагментов (`400 Bad Request`):
```json
{
  "error": "Недостаточно фрагментов для активации бустера x3: требуется 4, доступно 1"
}
```
